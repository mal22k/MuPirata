================================================================================
 REPORTE TECNICO - SOURCE VIEJO CLIENTE MU ONLINE EX603 (SSeMU)
 Objetivo: documentar el source para construir una DLL inyectable con Lua embebido
           (UI custom, alquimia con trade, shops, efectos, packets)
================================================================================

Ruta del source analizado:
  SOURCE viejos/Source/Main_EX603/Main/        <- PROYECTO PRINCIPAL (el "Main")
  SOURCE viejos/Source/GetMainInfo_EX603/      <- Tool que genera la config del cliente
  SOURCE viejos/Source/Emulator/GameServer/    <- Source del GameServer (contraparte, S6)
  SOURCE viejos/Source/MHPClient, MHPServer/   <- Anti-cheat cliente/servidor
  SOURCE viejos/Util/                          <- Librerias (cryptopp, detours, mapm,
                                                   pugixml, sha1)

IMPORTANTE: El proyecto Main_EX603 NO es el cliente completo. Es una DLL de hooks
("Main") que se inyecta/engancha al main.exe original del cliente EX603 (Season 6
Episode 3). Esto es EXACTAMENTE la misma arquitectura que necesitas para tu DLL con
Lua: en vez de recompilar el cliente, se parchea memoria y se instalan hooks.
Todas las direcciones son del binario main.exe EX603 (build original del cliente).
Si tu cliente actual es la misma familia S6 Evercion (MuServerS6Evercion maxima),
las direcciones deberian coincidir. Si no, habria que re-localizarlas.

1.1 QUE ES EL PROYECTO
  - Solucion: Main.sln -> proyecto "Main" (Main.vcxproj)
  - Tipo de salida: DynamicLibrary (DLL), Release Win32
  - Toolset: v100 (Visual Studio 2010), formato proyecto VS2013 (ToolsVersion 12.0)
  - Windows SDK: 8.1, charset MultiByte, /O2 (MaxSpeed), Runtime MultiThreadedDLL
  - Definiciones: WIN32;NDEBUG;_WINDOWS;_USRDLL;MAIN_EXPORTS
  - OutputDir: ..\..\..\Program\MuServerEX603\Tools\GetMainInfo\Path\
  - Lenguaje: C++ (MSVC) con funciones __declspec(naked) en asm inline (patron
    habitual en este source para parches de memoria).

1.2 PUNTO DE ENTRADA
  - DllMain(HANDLE hModule, DWORD ul_reason, LPVOID lpReserved): solo guarda hins.
  - Funcion exportada que ejecuta TODO:
        extern "C" _declspec(dllexport) void EntryProc()
    (archivo Main.cpp). El cliente/launcher modificado la llama al arrancar.
  - Flujo de EntryProc():
      1) gProtect.ReadMainFile("ServerInfo.sse")  -> lee config cifrada del cliente
      2) ~50 SetByte/SetWord/SetDword/MemorySet/MemoryCpy  -> parches de bytes:
           - Cracks (mu.exe, GameGuard, ResourceGuard) y pantalla de login
           - Version del cliente (0x00E61F68..), IP:puerto, serial, nombre ventana
           - Limites de texto/items, fix de Ctrl, helper, etc.
      3) SetCompleteHook(0xE8, 0x005B96E8, &DrawNewHealthBar)   -> hook de dibujo
         SetCompleteHook(0xFF, 0x0065FD79, &ProtocolCoreEx)     -> hook de packets
      4) LoadReferenceAddressTable(hins, IDR_BIN1/2/3, NewAddressData1/2/3)
           -> aplica las tablas de direcciones embebidas como recursos "BIN"
      5) gCustomXxx.Load(m_MainInfo.CustomXxxInfo)  -> carga tablas custom
         (Effect, Item, ItemBow, ItemGlove, Jewel, Map, Monster, MonsterSkin,
          Tooltip, Wing, ItemStack, ItemValue)
      6) gPacketManager.LoadEncryptionKey("Data\\Enc1.dat")
         gPacketManager.LoadDecryptionKey("Data\\Dec2.dat")
      7) InitXxx() por modulo: ChaosBox, Common, EventEntryLevel, Font, HackCheck,
         Item, ItemBow, ItemGlove, Jewel, Map, Monster, PrintPlayer, Reconnect,
         Resolution, Shop, Wing.
      8) gProtect.CheckLauncher/CheckInstance/CheckClientFile/CheckPluginFile
      9) SetWindowsHookEx(WH_KEYBOARD, KeyboardProc, hins, GetCurrentThreadId())
         SetWindowsHookEx(WH_MOUSE,    MouseProc,   hins, GetCurrentThreadId())
     10) CreateThread(ReduceConsumeProc) -> libera working set cada 5s.

1.3 CONFIGURACION DEL CLIENTE (ServerInfo.sse)

 SECCION 5: PACKETS Y RED
================================================================================

5.1 ENVIO CLIENTE -> SERVIDOR (Protocol.cpp - DataSend)
  - Firmas: void DataSend(BYTE* lpMsg, DWORD size)  <- USAR ESTA para tus packets
  - Flujo interno:
      1) gPacketManager.AddData(lpMsg,size) -> copia a buffer interno (max 2048)
      2) gPacketManager.ExtractPacket(EncBuff):
            - Cabeceras: C1/C3 -> size=buff[1]; C2/C4 -> size=WORD(buff[1..2])
            - Aplica XOR header: m_buff[n] ^= m_buff[n-1] ^ m_XorFilter[n%32]
              (tabla fija de 32 bytes en PacketManager.cpp)
      3) Si es C3/C4 (encriptado):
            - Escribe serial: buff[1] o buff[2] = (*(BYTE*)MAIN_PACKET_SERIAL)++
              (MAIN_PACKET_SERIAL = 0x08793700)
            - gPacketManager.Encrypt(&send[2], &EncBuff[1], size-1)  (C3)
              o Encrypt(&send[3], &EncBuff[2], size-2)               (C4)
              -> expande cada bloque de 8 bytes a 11 bytes (bit-packing)
            - Reconstruye cabecera con el nuevo tamaño
      4) MySend(*(SOCKET*)(MAIN_ACTIVE_SOCKET+0x0C), send, size, 0)
            (MAIN_ACTIVE_SOCKET = 0x08793750)
  - Regla de oro: los packets C1/C2 van SIN encriptar; C3/C4 van encriptados.

5.2 RECEPCION SERVIDOR -> CLIENTE (Protocol.cpp - ProtocolCoreEx)
  - El cliente original despacha con ProtocolCore(head, msg, size, key) en 0x00663B20.
  - La DLL reemplaza la llamada en 0x0065FD79:
        SetCompleteHook(0xFF, 0x0065FD79, &ProtocolCoreEx);
  - ProtocolCoreEx(BYTE head, BYTE* lpMsg, int size, int key):
        switch(head) { case X: ... } ; y para cabeceras con sub-head usa
        lpMsg[3] (si C1) o lpMsg[4] (si C2).
        Al final: return ProtocolCore(head, lpMsg, size, key);  // deja pasar el resto
  - ESTE es el punto de hook para interceptar/inyectar opcodes custom.

5.3 CIFRADO (PacketManager.cpp - CPacketManager) - algoritmo MU clasico
  - Claves: Data\\Enc1.dat (encriptar) y Data\\Dec2.dat (desencriptar).
    Formato archivo: header WORD 4370 + size DWORD; luego 3 tablas de 4 DWORDs
    (Modulus, Key, Xor) cada una XOR-eada con m_SaveLoadXor =
    {0x3F08A79B, 0xE25CC287, 0x93D27AB9, 0x20DEA7BF}.
  - EncryptBlock: 8 bytes -> 11 bytes. 4 DWORDs calculados con
    Enc = (((Xor^palabra)^valor)*Key) % Modulus (encadenado), empaquetados
    a bits (16 bits + 2 bits) y checksum (XOR de los 8 bytes ^ size ^ 0x3D).
  - DecryptBlock: inversa + verificacion de checksum.
  - XorData: filtro XOR de cabecera (m_XorFilter[32] fijo).

5.4 ESTRUCTURAS DE PACKET (Protocol.h)
  - PBMSG_HEAD  : type(C1), size(BYTE), head        ; set()=plano, setE()=C3
  - PSBMSG_HEAD : type, size, head, subh            ; set()=C1, setE()=C3
  - PWMSG_HEAD  : type(C2), size[2], head           ; set()=C2, setE()=C4
  - PSWMSG_HEAD : type, size[2], head, subh         ; set()=C2, setE()=C4
  - Macros de numero: SET_NUMBERHB/LB/HW/LW/HDW/LDW y MAKE_NUMBERW/DW/QW.
  - Todos los structs de recv usan campos "//EXTRA" (DWORD View*) que el cliente
    guarda en variables globales para dibujar la UI (ver 6.6).

6.1 INVENTARIO (cliente: sin modulo propio; todo via hooks + memoria)
  - Archivo principal: Item.cpp (InitItem, InitItemBow, InitItemGlove, InitJewel,
    InitWing). No hay funciones de slots en el source: el manejo de slots es del
    cliente original; la DLL hookea puntos de item (modelo, textura, color,
    efecto, texto de socket) y lee/escribe la estructura de item en memoria.
  - Layout de un item en memoria (usado por los hooks de Item.cpp/Shop.cpp):
        +0x00  index  (WORD)             +0x02  level/opciones (DWORD)
        +0x16  durabilidad (BYTE)        +0x17  excellent (GET_ITEM_OPT_EXC)
        +0x22  byte arco especial        +0x25/0x26/0x36  opciones (alas)
        +0x49  flag socket               +0x4A..+0x4E  socket options (5)
    Macros: GET_ITEM(x,y), GET_ITEM_MODEL(x,y), ITEM_BASE_MODEL=1171,
            MAX_ITEM_TYPE=512, GET_ITEM_OPT_LEVEL(x)=((x>>3)&0xF),
            GET_ITEM_OPT_EXC(x)=x-(x&0x40)
  - Tabla global de items: *(DWORD*)0x08128AC0 + 0x54*index

9.3 REQUISITOS / CAMPOS CLAVE DE ServerInfo.sse (MAIN_FILE_INFO)

  ClientName[32]   : nombre del main.exe (p.ej. "main.exe")
  ClientNameCRC    : CRC32 (1024 bytes) de main.exe  -> CheckClientFile()
  PluginName[3][32]: nombres de hasta 3 DLLs plugin
  PluginNameCRC[4] : CRC32 (1024 bytes) de cada plugin -> CheckPluginFile()
  LauncherStart    : bit0 = exige launcher (mutex LauncherMutex)  -> CheckLauncher()
                     bit1 = control de instancia unica (mutex "SSEMU_MAIN_S6ENG_<IP>")
  LauncherMutex[32]: nombre del mutex del launcher
  (todos los demas campos: IP, puerto, version, serial, teclas, tablas custom...)

  Detalles del CRC: CRC32.FileCRC(name,&crc,1024) calcula el CRC de los primeros
  1024 bytes del archivo. Se usa para main.exe y para cada plugin.
