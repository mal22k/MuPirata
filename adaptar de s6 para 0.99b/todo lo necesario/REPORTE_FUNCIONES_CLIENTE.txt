 1) MOUSE / INPUT
================================================================================
NOMBRE        : MouseClick (HelperMouseClick del source viejo)
ARCHIVO       : Main_EX603/Main/Common.cpp (la llama como 0x007D2920)
OFFSET VIEJO  : 0x007D2920 (funcion); el source viejo hookea el call en 0x007D2B0C
FIRMA         : char MouseClick(char* This)  (__thiscall, 1 arg, retorna char)
PARAMETROS    : This = puntero a la ventana/interfaz del cliente
RETORNO       : char (0 = click consumido / no procesado)
DESCRIPCION   : Funcion del cliente que procesa los clicks del raton. El source
                viejo la llama tras comprobar que las ventanas 8/9 (helper/NPC
                shop) no estan abiertas: si lo estan, devuelve 0 y el click se
                traga. Patron canonico para "bloquear clicks".
CONFIRMADO    : SI (offset resuelve en .text del main.exe actual)
PATTERN       : hook del CALL SITE que la invoca (0x007D2B0C en el source viejo;
                si no, escaneo del .text por E8/E9 -> 0x007D2920). Es el MISMO
                patron que usan los hooks de render/packets del plugin y el que
                usa el propio Main_EX603 (SetCompleteHook(0xE8, 0x007D2B0C, ...)).
COMO VALIDAR  : check_offsets.ps1 + en vivo: registrar un rect con UI.BlockMouse
                y comprobar que el juego no ataca al clickear una ventana custom
COMO EXPONER  : Ya expuesto: hook interno (FASE 6) + UI.BlockMouse/ConsumeClick
RIESGO        : BAJO-MEDIO. NO se usa jmp-hook de la funcion (se descarto por
                riesgo de partir una instruccion multi-byte del prologo): solo se
                redirige un call E8/E9 existente con chaining y SetCompleteHook
                (0xFF). Si no hay call site, la feature se desactiva y loguea.
                Asuncion documentada: la funcion original se invoca como thiscall
                (patron del source viejo); un hook previo (main.dll) como cdecl.
PRIORIDAD     : ALTA (implementada; verificacion en vivo pendiente)

NOMBRE        : ClicMouseProc (ataque con click derecho)
ARCHIVO       : Main_EX603/Main/Common.cpp
OFFSET VIEJO  : usa MAIN_SCREEN_STATE + ClicMouseTime (envia C1:04)
FIRMA         : void ClicMouseProc()
PARAMETROS    : -
RETORNO       : void
DESCRIPCION   : Envia el packet de ataque C1:04 (throttled 1000ms). Es el click
                derecho que dispara el WH_MOUSE hook de main.dll.
CONFIRMADO    : PARCIAL (en el cliente actual el click derecho se envia desde
                main.dll; nuestro bloqueo de clicks evita que llegue a esta capa)
PATTERN       : -
COMO VALIDAR  : en vivo: click derecho sobre una ventana custom con bloqueo activo
COMO EXPONER  : no se expone (queda bloqueado por el hook de MouseClick)
RIESGO        : BAJO (no se toca)
PRIORIDAD     : BAJA (cubierta por el bloqueo de clicks)

NOMBRE        : KeysProc / IconProc (sustitucion de GetAsyncKeyState / LoadIcon)
ARCHIVO       : Main_EX603/Main/Main.cpp
OFFSET VIEJO  : SetDword(0x00D226C8, KeysProc) / 0x00D2265C
FIRMA         : int KeysProc(int vk)
DESCRIPCION   : main.dll sustituye GetAsyncKeyState del cliente. Relevante para
                saber que el polling de on_key/on_click usa el mismo estado que
                ve el juego.
CONFIRMADO    : PARCIAL (punteros en .rdata; el plugin no los necesita)
COMO EXPONER  : no aplica (Input.KeyPressed ya usa GetAsyncKeyState directo)
RIESGO        : BAJO
PRIORIDAD     : BAJA

ARCHIVO       : NO documentada en el source viejo (codigo cerrado del main.exe)
OFFSET VIEJO  : -
FIRMA         : -
DESCRIPCION   : El source viejo documenta la TABLA GLOBAL de items por INDICE
                (Item.cpp): *(DWORD*)0x08128AC0 + 0x54*index = struct de item
                (modelo/opciones/durabilidad). NO documenta la matriz de SLOTS
                del inventario del personaje (donde viven los items equipados).

NOMBRE        : ItemBowInventory / tablas de item (referencia)
ARCHIVO       : Main_EX603/Main/Item.cpp
OFFSET VIEJO  : hook 0x005CC8E4; tabla 0x08128AC0 + 0x54*index
FIRMA         : DWORD ItemStruct = *(DWORD*)0x08128AC0 + 0x54*(*address)
DESCRIPCION   : Layout de ITEM en memoria (documentado): +0x00 index (WORD),
                +0x02 level/opciones (DWORD), +0x16 dur (BYTE), +0x17 excellent.
                ItemInfo de 12 bytes en packets: [0..1] index LE, [2] level
                ((x>>3)&0xF), [3] durabilidad.
CONFIRMADO    : PARCIAL (layout de ItemInfo de packets confirmado por el layout
                del GameServer; la tabla por indice resuelve como direccion)
COMO EXPONER  : Client.GetTradeItem(slot) devuelve {slot,index,level,dur} desde
                el packet C1:39 (cache de estados)
RIESGO        : BAJO (parsing con guardas de tamano)
PRIORIDAD     : MEDIA (trade implementado; inventario pendiente de RE)
