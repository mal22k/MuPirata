// FUNCION REAL DEL SISTEMA
// Define joyas custom que se arrastran desde el inventario sobre un item destino.
// Si el item cumple las restricciones de la seccion 0, el servidor consume la
// joya y aplica el resultado de exito o fallo segun la tasa por AccountLevel.
//
// FLUJO AL USAR UNA JOYA
// 1. ItemManager detecta que el item usado es una joya custom.
// 2. ObjectManager valida si el item destino puede recibir esa joya.
// 3. Calcula exito con RateAL0-RateAL3 segun el AccountLevel del jugador.
// 4. Si acierta, aplica la seccion 1.
// 5. Si falla, aplica la seccion 2.
// 6. La joya se consume si la aplicacion fue valida.
//
// ITEMINDEX GLOBAL
// JewelItem es indice global: GET_ITEM(Grupo, Index) = (Grupo * 512) + Index.
// Las joyas actuales 7412-7420 corresponden al grupo 14, indices 244-252.
//
// TIPOS DE ITEM PERMITIDOS
// Weapon controla armas, Armor controla armaduras y Wing controla alas/custom wing.
// Valor 1 permite ese tipo; valor 0 lo bloquea; * equivale a sin restriccion.
//
// RATE POR TIPO DE CUENTA
// RateAL0 = cuenta normal/free.
// RateAL1 = VIP nivel 1.
// RateAL2 = VIP nivel 2.
// RateAL3 = VIP nivel 3.
// En la configuracion actual todas estan a 100%, por eso no hay fallo real.
//
// SECCION 2 VACIA
// La seccion de fallo esta vacia. Eso significa que, si una joya fallara, no le
// restaria nivel/skill/luck/option al item. La joya igual se consume cuando la
// aplicacion es valida.
//
// EXCELLENT, ANCIENT Y SOCKET
// Excellent agrega opciones al azar segun la cantidad indicada. En alas el maximo
// puede ser menor que 6 por reglas internas del source.
// Ancient usa bits de SetOption. Valores actuales: 5 para ancient tipo 1 y 6
// para ancient tipo 2.
// Socket agrega sockets vacios 0xFE en posiciones libres.
//
// PRECIO Y MODELO
// SalePrice reemplaza el precio de venta de la joya.
// Model es el nombre usado por el cliente para identificar/mostrar el modelo.
//
// REGLAS DE EDICION
// - Use indices 0-14 como maximo, salvo que se aumente MAX_CUSTOM_JEWEL.
// - No repita JewelItem; el sistema busca la primera coincidencia por item.
// - Use * solo donde el parser acepta -1/sin restriccion.
// - Los bloques deben estar en orden 0, 1, 2 y terminar con end.
// ============================================================================
